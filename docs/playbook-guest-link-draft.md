# Guest link draft: private lifecycle and isolated unavailable route

This is NOT a releasable guest player. Issuance and playback remain unavailable, regardless of environment configuration. No live token, grant, Storage permission or production record has been changed.

## Implemented source boundaries
- guestWorkoutCapability.ts: digest-only, expiring/revocable/rotatable per-assignment capability core. Final admission requires one consistent grant/assignment/session/plan snapshot. Pin/scheduled/carry-forward order matches the member player. Zoom-ended status does not imply workout completion. Internal admission is never a public response or permission to return a full document.
- guestCapabilityStore.ts and guestAssignmentLifecycle.ts: real Firestore transaction adapter, private generation, creation-time binding, atomic membership replacement. Existing protected plans can remove members even when the global rollout is off. First activation defaults off.
- firestore.rules: Playbook and roster-member rules change. Clients cannot create/change server locks; protected membership/coach fields and locked roster UID/coach/archive fields cannot be changed directly. Private version/grant collections remain covered by default deny. Existing unlocked plans and members retain legacy writes.
- Coach Build add/remove and SchedulePanel membership edits use updatePlaybookMembers. Protected plans use server transaction, no fallback after rejection. The Build menu displays guest access unavailable. Standalone confirmation controls distinguish expiring guest links from permanent authenticated links; canRevoke is independent of canIssue.
- Four management endpoints are exported: status (always canIssue:false), owner-scoped revocation (works during rollout shutdown), gated assignment management, and owner-scoped roster archive/restore. No issue endpoint or anonymous workout/media Cloud Function is exported.
- /guest-workout is a separate static unavailable page: no Expo/Auth/Sentry or third-party scripts, no-referrer/no-store/noindex, camera/mic denied, strict script hash CSP, fragment/query cleared from the current history entry before rendering. Hosting rewrite prevents nested guest paths falling into the SPA. Both service workers bypass it and generated precache excludes it. Telemetry filters also suppress stale guest URLs/credential fields from existing app events.

## Assignment writer inventory
Current source inspection identifies Build add/remove, SchedulePanel writeMembers (routed), Build create/duplicate (new document with no grants), enrollment clone (new document; server guest lock stripped), Build delete (future recreated document has different server creation time), template sync (workoutIds/musicStyle/description only), and detach (unsynced only). Booking creates sessions and does not mutate Playbook member assignment. The private generation is changed synchronously, not by a trigger. Future server assignment writers must use the transaction; this is not a claim that arbitrary Admin SDK writes can be prevented by Firestore rules.

## Roster identity lifecycle
Private guest_roster_versions binds the roster document's server creation time, coach, UID and generation. Combined assignment/roster generation is checked on issue and every resolution. Coach A to B to A, UID changes and archive/restore never reactivate old grants. Delete/recreate fails even when copied public lock fields are identical. Safe profile edits preserve access.

Source writer inventory: members.tsx edits ordinary profile fields directly, but archive/undo now use updateRosterArchive and the server transaction for locked records. claimMemberAccount and sendMemberInvite update UID through updateRosterIdentity. Intake creates new documents. No existing client coach-transfer screen was found; direct identity changes on locked records are intentionally denied. A future transfer workflow must call the authoritative transaction. Arbitrary privileged Admin writes are outside rules enforcement and must obey that contract. No trigger delay is relied upon.

## Bounded offline media slice
Existing MovementForm/BulkMovementUpload/createMovementFromVideo produce movements/{coachId}/... objects and coach-owned movement metadata. WorkoutFolderPage/FollowAlongVideoUploadSheet use workouts/{coachId}/... objects. Stored Firebase download URLs are parsed locally into paths only for the configured bucket; their token/query is discarded, never fetched or returned. Global/shared/cross-coach assets, external hosts, traversal and foreign buckets fail closed.

- guestWorkoutDelivery loads the selected coach-owned workout and canonical referenced coach-owned movements, projects only prescription fields and opaque asset IDs. No notes, member identity, Zoom, stored URL or write state is exposed. Voice/music and video calls are explicitly unsupported.
- guestStorageReader uses the injected Admin bucket and generation-pinned bounded reads (1 MiB/request, 100 MiB object ceiling, 10-second timeout). Admission and selected asset ownership are rechecked before and after every read; cancellation/revocation/asset replacement discards buffered bytes before response. No public/signed URLs, metadata mutation or Storage permission change.
- guestDeliveryHttp is an injectable, default-disabled handler, NOT a Cloud Function export. Same-origin POST/header-only capability, strict action/body validation, generic errors, private no-store/no-referrer responses. It never logs the capability. No Hosting API rewrite exists.
- guestMediaClient is a draft-only memory/header adapter, not wired into the unavailable page. Fixed same-origin endpoints, no cookies/redirects/cache/referrer, bounded response consumption and Blob assembly (25 MiB browser ceiling), single-flight renewal, independent 25-second maximum admission expiry, abort and Blob revocation on close. A UI must call close on navigation/pagehide and remove media elements on its onUnavailable callback. No completion/progression method exists.

Remaining implementation/review gates: connect the isolated player shell and HTTP boundary under a hard-disabled deployment gate, install navigation/pagehide teardown and renewal in that shell, verify actual supported synthetic video playback, load/seek/expiry and integrated privacy/cache behavior, then independent source review. Unsupported assets must remain unavailable rather than silently fall back to reusable URLs. This is implementation work, not missing external credentials or a provider requirement. Live issuance/access still needs separate approval; canIssue stays false and the current static page loads no workout.

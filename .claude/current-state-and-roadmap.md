# GoArrive Current State & Roadmap

_Last refreshed: 2026-08-11._

## What Is Built and Working
The platform has a strong operational backbone. The following systems are fully functional and deployed to production at `goarrive.fit` (also `goarrive.web.app`).

**Plans**: The full plan builder with pricing engine is operational, including CTS (Commit-to-Save) opt-in, plan sharing, 3-month contracts with dynamic referral copy, and intake-to-plan flow.

**Scheduling**: Recurring slots, session instance generation, Zoom room allocation, phase transitions, skip requests, no-show detection, and Google Calendar sync (posting and conflict checking) are all live. A P0 fix batch (sync field, callable invoker IAM, conflict UI, redirects) landed in July.

**Playbook Scheduling & Booking** (Phases 3a + 3b, shipped via PR #208): Coaches attach a schedule to a playbook — a Calendly-style weekly-hours availability editor with date-specific overrides, per-day flexible durations, weekly session caps, book-ahead windows, and Record Sessions toggle, all auto-saving. A public booking link (token-based, revocable) lets members and guests book sessions with idempotent booking via `clientRequestId` and daily TTL cleanup of expired `booking_requests` dedupe docs. The coach scheduling panel supports drag-and-drop workout scheduling into day modules with mosaic tiles and instant live-swap preview. Members get a session page (`/live-session/**` hosting rewrite) with countdown, reschedule/cancel, and a Zoom-gated live player.

**Playbook Live View** (PR #207): Coach split-screen view (roster + workout) and a member player-with-Zoom PiP experience are in production. The member live-session page renders a 3-state UI (pre-session countdown, active session with player, post-session), which was restored after a merge-conflict clobber in the live-view ship (fix landed in the 2026-07-28 prod push). Live player state writes (member progress, current block/movement, completion) are wired to Firestore so the coach split-screen reflects real-time member activity.

**Session Lifecycle**: Session generation, allocation, reminders, and no-show detection are automated via scheduled Cloud Functions.

**Billing Foundation**: Stripe Connect (Standard mode) is integrated with checkout sessions, webhook handling, subscription management, dispute handling, and ledger entries. Prorated earnings caps with yearly admin configuration and automatic carryover are implemented. **Subscription Pause/Resume** (PR #233): coaches can pause and resume a member's Stripe subscription directly from `MemberDetail` — the UI shows a live-listening Pause/Resume button with loading state, backed by `pauseStripeSubscription` and `resumeStripeSubscription` Cloud Function callables that verify coach ownership via `coachId` claim, call `stripe.subscriptions.update` with `pause_collection`, and sync `pausedAt` to Firestore.

**Role-Based Auth**: Three roles (platformAdmin, coach, member) with custom claims, route guards, and Firestore security rules. Admin impersonation is fully functional and was hardened in July ("View as Coach true to coach" — rules grants + role mask, identity/settings fixes). Two P0 security audit batches (auth guards, impersonation, Stripe retry, completion-write integrity) shipped in early July.

**Admin Operations**: Coach management, profit share settings, yearly earnings cap configuration, per-coach module visibility (feature gating, including hiding the tab bar entirely when all gateable modules are off), dead letter queue, event log, and system health monitoring are available.

**Member Portal**: Home, sessions, plan view, payment selection, profile, checkout success, and a dedicated **member workouts page** (`app/(member)/workouts.tsx`) where members view and play assigned workouts.

**Workout Player**: `WorkoutPlayer.tsx` is fully wired into the member workouts page and public share links. It has been through an extensive hardening campaign: iOS audio unlock and autoplay-revocation recovery, audio queue deadlock fixes, frozen-video recovery (foreground resume + stall escalation), orientation/canvas scaling, 10s seek with block-boundary crossing, prescribed weight/reps display + speech, grab-equipment phase with AI-generated images, demo phase TTS cues, swap-sides playback, water breaks, Tabata blocks, and a spoken AI intro announcement. Live heart-rate monitoring via Web Bluetooth is in. A vitest regression suite covers video and TTS stability.

**Audio PiP Foundation** (PRs #231 — Phase 1): `useWorkoutTTS` now fans audio out in parallel from `voiceGain` and `musicGain` to a `MediaStreamAudioDestinationNode`, exposing `getPipAudioStream()` for Phase 2 canvas-stream PiP consumption. Speakers are unchanged — existing `.connect(audioCtx.destination)` calls are preserved; the fan-out disconnects on `resetAudioPool`. Phase 2 mounts a hidden canvas PiP video behind a staging flag (PRs #dde33be + #f53b11e on `feat/pause-contract-extend`).

**PWA**: The web app registers a service worker that auto-reloads open tabs on a new deploy, with the registration snippet injected into every exported route page — no more users stuck on stale bundles.

**Post-Workout Journal**: The Glow/Grow reflection (`PostWorkoutJournal.tsx`) is connected to the workout completion flow on both the member workouts page and guest share links (guest reflections with a signup nudge).

**Coach Review**: `CoachReviewQueue.tsx` is integrated into `MemberDetail`, with canonical `coachNote`/`reviewStatus` fields and optional coach notes on single workout assignments.

**Sharing**: Google-Docs-style workout share links (visibility, expiry, view counter, revoke), dynamic Open Graph images for link previews, and a guest play flow with glow-and-grow reflection capture. **Marketing Share Links** (PR #232): a new `shareType: 'marketing'` extends the share token system — coaches can toggle a marketing link with an optional email gate (name + email capture written to `marketing_leads` with public-create / coach-read Firestore rules) and a post-workout end-of-workout CTA (`WorkoutFunnelCTA`) that presents subscription options, booking options, and a discount code input. The share modal in `WorkoutFolderPage` gains marketing toggle + email gate toggle + subscription option builder.

**Public Routes**: Intake form (8-step wizard), coach signup/application, shared plan view, workout share links, the public booking page (`app/book` — Calendly-parity guest booking flow), and the member live-session page. The intake route (`/intake/[coachId]`) now supports **coach-branded deeplinks**: `?ref=` and `?source=` URL params carry program attribution (e.g. `?ref=1on1-pc` from a booker subdomain), saved to `intakeSubmissions` so the coach can see which program drove the lead. When a `coachId` is present the intake header shows the coach's name and photo instead of the GoArrive logo.

**Coach Discovery** (PR #229): A public `/coach-discovery` route delivers a phone-first, 27-scene narrative experience across seven acts — restrained motion, sticky member journey, presentation mode, progress controls, keyboard navigation, reduced-motion handling, and a final `/coach-apply` CTA. Includes current compensation tiers and cap/referral qualifiers; Team Builder is marked planned but not live. Self-hosted licensed fonts, semantic/lazy WebP images, scoped analytics hooks, and WCAG A/AA accessibility.

**Build System**: The unified Build tab is live, combining movements and workouts into a single creative workspace. Features include bulk movement upload with AI auto-analysis, dynamic workout thumbnail grids (4:5 aspect ratio), equipment/muscle/difficulty filters, and most-recently-edited sorting. **Folders v2** shipped: universal drag-and-drop of all asset types into folders (including iOS springboard-style drag), folder tiles rendered as mini still-photo mosaics of their contents, drag-to-back to move assets up a level, and instant re-sort on drop. **Folder grid drag** is now live: folder tiles themselves are draggable within the Build tab grid to reorder them, using a drop tray with a pinned height so iOS Safari cannot stretch it upward. **Playbooks** (workouts-only folders with drill-in, ordered `workoutIds`, drag membership, assign-on-create) shipped as Phase 2, and now carry the Phase 3 scheduling/booking and live-view systems described above. A **three-dot settings menu** (archive, move-to-folder, manage members, revoke/regenerate booking link) shipped via PR #216. The coach scheduling panel's per-day module cards and workout-icon-only drag (with live-swap animation) were restored after a global-times regression was reverted. **Grid card icon treatment**: all three card types now render their type icon inline to the left of the title — folder (orange folder shape), playbook (purple), and workout (barbell in light sky blue #7DD3FC) — making asset types distinguishable at a glance without opening them. **Subscription-Program Playbook Folders** (PR #234): a new `PlaybookFolder` asset type in the Build tab. Coaches create a Playbook Folder that holds template playbooks (one per subscription path) and automatically generates member-specific copies with status badges. A settings panel lets coaches toggle sync and edit email drip templates for each template playbook. New `playbook_folders` and `playbook_folder_members` Firestore collections with matching rules. Enrollment flow is stubbed, coming in Phase 4.

**Movements**: Placeholder movements (create without video, add-video-later with AI confirm-merge, "Video Needed" badge, player logo fallback), duplicate-name soft warning, iPhone HEVC-to-H.264 transcode on upload, static poster thumbnails with lazy GIF swap, inline editing from inside a workout, and Duplicate action.

**Equipment Library** (PR #218): Grab-equipment input history and a shared equipment image library are in production. Coaches can filter, edit, drag-and-drop to reorder, rename, and delete-confirm equipment entries. The library includes search, icon corrections, scroll fixes, and performance cleanup (rounds 4–6).

**Workout Duration Estimate** (PR #219): The build-time duration estimate now correctly accounts for swap-sides split/duplicate mode, so coaches see accurate time predictions for workouts with bilateral movements.

**AI Features**: Movement variations via Runway (build a variation from an existing movement, background-mode polling that persists outputs, motion remix from a still frame), AI workout music via Mubert (18 styles, no-repeat track pools that change songs through the workout with a deterministic per-workout order, in-player music panel with skip/like/dislike/volume/style-change, per-user `musicPrefs` + shared per-workout `workoutMusicFeedback` dislikes — music genre revert on style switch fixed in PR #233), AI-generated spoken workout intro announcements, grab-equipment AI images, and follow-along video blocks.

**Zoom**: RTMS backend + Meeting SDK embedded join are integrated; the player joins via Client View for iOS Safari camera support. True round-robin room allocation (lastUsedAt LRU + bot-pool preference) is live (PR #205). The "My Zoom Account" coach UI has been removed — Zoom identity is hardcoded to the coach's login email (PR #201). See `docs/ZOOM_APPS_MAP.md` for the three-app layout.

**Coach Launch & Comms**: Full 6-module practical post-agreement coach setup guide (`app/(app)/coach-setup.tsx`) with a `CoachSetupCard` dashboard widget that tracks onboarding progress (PR #223). The guide includes a **GoArrive Certified Coach (GCC)** module (replacing a generic ISSA cert recommendation) with a prestigious branded design, GoArrive logo, and online coaching niche framing. Coach profile editing now persists correctly (Firestore permission fix), and instant photo/logo preview is live with an upload overlay. Automated branded coach welcome email, Coach Agreement v2, weekly "What's New" digest, and a coach feedback loop (in-app feedback page, admin email, shipped-note autofill) are all live.

**Member Management**: Duplicate email prevention, plus Send Invite / Password Reset links from the coach member hub so coach-created members can log in.

## What Is Still Missing
**Playbook Folder Phase 4 — Enrollment Flow**: The subscription-program enrollment flow is stubbed; Phase 4 will wire member enrollment into the Playbook Folder system.

**In-App Messaging**: No direct messaging between coach and member exists within the app (the coach feedback loop is coach-to-platform, not coach-to-member chat).

**Progress Photos/Measurements**: No system for tracking visual or metric-based progress.

**Live Push Notifications (Server-Side)**: Push notifications are still mock-only on the server. Client-side registration exists, but server-side sending is not live.

**Monthly Billing Close**: No automated monthly billing reconciliation process.

**Native Mobile Apps**: The platform is web/PWA only; no App Store or Play Store builds.

## Build Priority Order
When deciding what to build next, follow this priority order:

| Priority | Area | Rationale |
|---|---|---|
| 1 | Playbook Folder Phase 4 — enrollment flow | Phase 3 shipped; enrollment is the final piece to close the subscription-program loop. |
| 2 | Workout player quality and reliability | Ongoing hardening — iOS audio/video edge cases keep surfacing; keep the regression suite growing. Audio PiP Phase 2 (canvas-stream) is in flight. |
| 3 | Marketing funnel polish | Marketing share links, email gate, and end-of-workout CTA are live; next is lead management and conversion tracking in the coach dashboard. |
| 4 | Coach-review speed and acknowledgment loops | Review queue exists in MemberDetail; make review-and-respond the fastest path in the coach's day. |
| 5 | Notification reliability | Push is mock-only server-side; email and SMS are conditional. |
| 6 | Coach command center refinement | Continue replacing "Coming Soon" tiles in MemberDetail. |
| 7 | Deeper admin visibility | Analytics tab, recording dashboard. |
| 8 | Secondary expansions | Messaging, progress photos, check-in calls, native apps. |

# GoArrive Current State & Roadmap

_Last refreshed: 2026-08-15._

## What Is Built and Working
The platform has a strong operational backbone. This section records capabilities that are built and working at the most recently verified level; an item may be merged to `main`, available on staging, or deployed to production. Deployment status is stated explicitly for recent items and must not be inferred from a merge alone.

**Plans**: The full plan builder with pricing engine is operational, including CTS (Commit-to-Save) opt-in, plan sharing, 3-month contracts with dynamic referral copy, and intake-to-plan flow.

**Scheduling**: Recurring slots, session instance generation, Zoom room allocation, phase transitions, skip requests, no-show detection, and Google Calendar sync (posting and conflict checking) are all live. A P0 fix batch (sync field, callable invoker IAM, conflict UI, redirects) landed in July.

**Playbook Scheduling & Booking** (Phases 3a + 3b, shipped via PR #208): Coaches attach a schedule to a playbook — a Calendly-style weekly-hours availability editor with date-specific overrides, per-day flexible durations, weekly session caps, book-ahead windows, and Record Sessions toggle, all auto-saving. A public booking link (token-based, revocable) lets members and guests book sessions with idempotent booking via `clientRequestId` and daily TTL cleanup of expired `booking_requests` dedupe docs. The coach scheduling panel supports drag-and-drop workout scheduling into day modules with mosaic tiles and instant live-swap preview. Members get a session page (`/live-session/**` hosting rewrite) with countdown, reschedule/cancel, and a Zoom-gated live player.

**Playbook Live View** (PR #207): Coach split-screen view (roster + workout) and a member player-with-Zoom PiP experience are in production. The member live-session page renders a 3-state UI (pre-session countdown, active session with player, post-session), which was restored after a merge-conflict clobber in the live-view ship (fix landed in the 2026-07-28 prod push). Live player state writes (member progress, current block/movement, completion) are wired to Firestore so the coach split-screen reflects real-time member activity.

**Session Lifecycle**: Session generation, allocation, reminders, and no-show detection are automated via scheduled Cloud Functions.

**Billing Foundation**: Stripe Connect (Standard mode) is integrated with checkout sessions, webhook handling, subscription management, dispute handling, and ledger entries. Prorated earnings caps with yearly admin configuration and automatic carryover are implemented. **Subscription Pause/Resume** (PR #233): coaches can pause and resume a member's Stripe subscription directly from `MemberDetail` — the UI shows a live-listening Pause/Resume button with loading state, backed by `pauseStripeSubscription` and `resumeStripeSubscription` Cloud Function callables that verify coach ownership via `coachId` claim, call `stripe.subscriptions.update` with `pause_collection`, and sync `pausedAt` to Firestore. **Subscription Pause Hardening** (PR #253; merged to `main`, deployment not independently verified in this refresh): all downstream schedule phases are shifted on resume so the calendar stays coherent, and a server-side observability log records the extension length. Pause extensions are intentionally uncapped per Devin's explicit "No stop" decision; long extensions surface in logging rather than being rejected. **Lapsed-Payment Handling** (PR #244): Full end-to-end lapse pipeline when a Stripe subscription goes `past_due`/`unpaid` — emails the member via Resend (`handleInvoicePaymentFailed`), writes a `notification_log` doc (type: `member_payment_lapsed`) for the coach, pauses all ready `drip_email_queue` docs (`dripPaused: true`) so drip emails skip the member, and adds a red PAUSED badge on member list rows plus a PAUSED banner on the member-plan page. Auto-recovery runs when `customer.subscription.updated` fires with `status: active` — clears all lapse flags and un-pauses drip docs.

**Role-Based Auth**: Three roles (platformAdmin, coach, member) with custom claims, route guards, and Firestore security rules. Admin impersonation is fully functional and was hardened in July ("View as Coach true to coach" — rules grants + role mask, identity/settings fixes). Two P0 security audit batches (auth guards, impersonation, Stripe retry, completion-write integrity) shipped in early July.

**Admin Operations**: Coach management, profit share settings, yearly earnings cap configuration, per-coach module visibility (feature gating, including hiding the tab bar entirely when all gateable modules are off), dead letter queue, event log, and system health monitoring are available.

**Member Portal**: Home, sessions, plan view, payment selection, profile, checkout success, and a dedicated **member workouts page** (`app/(member)/workouts.tsx`) where members view and play assigned workouts.

**Workout Player**: `WorkoutPlayer.tsx` is fully wired into the member workouts page and public share links. It has been through an extensive hardening campaign: iOS audio unlock and autoplay-revocation recovery, audio queue deadlock fixes, frozen-video recovery (foreground resume + stall escalation), orientation/canvas scaling, 10s seek with block-boundary crossing, prescribed weight/reps display + speech, grab-equipment phase with AI-generated images, demo phase TTS cues, swap-sides playback, water breaks, Tabata blocks, and a spoken AI intro announcement. Live heart-rate monitoring via Web Bluetooth is in. A vitest regression suite covers video and TTS stability. **iOS Safari Backgrounding Fixes** (PRs #258 and #259; merged to `main`, not production-verified): voice-bus audio elements bypass the Web Audio graph on iOS Safari (UA-sniffed, excluding CriOS/FxiOS/EdgiOS) and play through the native HTMLAudioElement pipeline. PR #259's v3 dual-element handoff keeps foreground music on the graph for player controls while a gesture-blessed native shadow element takes over during backgrounding. Exact-head staging and physical-iPhone Case D passed before #259 merged as `68441d7`, but the device pass still observed an audible volume jump at the handoff; that seam remains unresolved. Production handoff remains off by default, and these merge/device results do not establish a production deployment.

**Audio PiP Foundation** (PRs #231 — Phase 1): `useWorkoutTTS` now fans audio out in parallel from `voiceGain` and `musicGain` to a `MediaStreamAudioDestinationNode`, exposing `getPipAudioStream()` for Phase 2 canvas-stream PiP consumption. Full Phase 2 PiP for members remains behind the staging flag pending QA sign-off. **Pass 1 gate (PR #289; merged to `main` 2026-08-15, staging deploy):** `usePipCanvasStream` and the hidden `<video>` are now gated on `isPiP` — the rAF loop and hidden video only spin up once the `enterpictureinpicture` event fires, not from player mount. **PWA**: The web app registers a service worker that auto-reloads open tabs on a new deploy, with the registration snippet injected into every exported route page — no more users stuck on stale bundles.

**Post-Workout Journal**: The Glow/Grow reflection (`PostWorkoutJournal.tsx`) is connected to the workout completion flow on both the member workouts page and guest share links (guest reflections with a signup nudge).

**Coach Review**: `CoachReviewQueue.tsx` is integrated into `MemberDetail`, with canonical `coachNote`/`reviewStatus` fields and optional coach notes on single workout assignments.

**Public Routes**: Intake form (8-step wizard), coach signup/application, shared plan view, workout share links, the public booking page (`app/book` — Calendly-parity guest booking flow), and the member live-session page. ## What Is Still Missing
**In-App Messaging**: No direct messaging between coach and member exists within the app (the coach feedback loop is coach-to-platform, not coach-to-member chat).

**Progress Photos/Measurements**: No system for tracking visual or metric-based progress.

**Live Push Notifications (Server-Side)**: Push notifications are still mock-only on the server. Client-side registration exists, but server-side sending is not live.

**Monthly Billing Close**: No automated monthly billing reconciliation process.

**Native Mobile Apps**: The platform is web/PWA only; no App Store or Play Store builds.

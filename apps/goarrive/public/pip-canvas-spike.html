Canvas captureStream + PiP spike

Case 7 companion to pip-spike.html. Tests whether iOS Safari (any UA) can play a canvas.captureStream() MediaStream in a <video> and enter Picture-in-Picture with live audio. Answers the WebKit-bug-181663 question definitively on-device.
CASE 7 Canvas → captureStream → <video srcObject> → PiP
A canvas is animated live via requestAnimationFrame with a moving shape plus a running frame counter, so a frozen frame is instantly distinguishable from a live one. A 440Hz oscillator is added as an audio track through a MediaStreamAudioDestinationNode, so audio and video pipe through together. Zero dependencies; failure is unambiguously iOS.
PASS — PiP window opens, the animation keeps moving inside it, audio is audible. Canvas-stream path is viable on iOS; the usePipCanvasStream.ts:60 UA-sniff is stale.
FROZEN/BLACK — PiP opens but the frame is frozen or the tile is black. WebKit bug 181663 is still live; canvas path is dead on iOS. Ship the render pipeline instead.
REJECT — play() or requestPictureInPicture() rejects. Same conclusion; the error name below tells us which wall we hit.
